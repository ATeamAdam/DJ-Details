DJ Details Codex Task List
==========================

Purpose
-------
This file is the working task list for Codex. Future Codex sessions should read this file first, choose the next suitable unchecked task, complete it, tick it off, and commit the completed changes.

Operating instructions for Codex
--------------------------------
1. Read this file at the start of a DJ Details maintenance session.
2. Choose the highest-priority unchecked task that can be completed safely.
3. Complete one task at a time unless tasks are tightly coupled.
4. When a task is completed, change its checkbox from "[ ]" to "[x]" and add a short completion note/date if useful.
5. If new follow-up tasks are discovered and cannot be completed immediately, add them to "Discovered follow-up tasks".
6. Commit completed changes with a clear commit message.
7. Keep the scraper stable. Do not parallelise the 1001Tracklists alphabet/list scan unless explicitly requested.
8. Prefer boring, reliable improvements over aggressive speed changes.
9. Avoid changes that increase CAPTCHA risk unless the user explicitly accepts the tradeoff.
10. Preserve data. If a task touches database paths, migrations, or runtime storage, avoid destructive operations and add migration/back-up notes where needed.

Recommended strategy
--------------------
Keep the 1001Tracklists DJ list scan single-threaded and stable. Improve reliability, visibility, scheduling, persistence, and Magic Emailer integration around it.

Current priority tasks
----------------------
[x] Fix pipeline completion ordering and persisted Magic queue counters. Completed 2026-06-17.
    The email stage currently emits "scrapingComplete" before the Magic Emailer queue summary is generated.
    This can make the UI and pipeline_runs table mark the run complete before emailsQueuedForMagic/skippedSynced are persisted.
    Implement this so completion has one finalization point:
    - email scraping finishes
    - Magic Emailer queue summary is generated
    - pipeline run stats are updated
    - pipeline_runs is marked success
    - UI receives the final complete state
    Make sure a failed Magic queue step records a failed/partial run instead of silently succeeding.

[x] Make pipeline completion events single-owner. Completed 2026-06-17.
    Several stages emit their own completion events and the server also emits completion events after awaiting them.
    Choose one owner, preferably the server/orchestrator, for final stage completion messages.
    Remove or suppress duplicate completion emissions for:
    - scraperComplete
    - updaterComplete
    - scrapingComplete/full pipeline complete
    Ensure this does not break progress, reconnect snapshots, or stop handling.

[x] Harden SQLite migrations and schema bootstrapping.
    Replace ad-hoc callback migration chains with promise-backed, transactional migrations.
    Add a schema version table or migration ledger.
    Add migration safety for:
    - magic_emailer_sync status/check-constraint migration
    - djs profile failure columns
    - pipeline_runs table
    Migrations should fail clearly and avoid leaving renamed/half-migrated tables behind.

[ ] Make Magic Emailer queueing incremental.
    queueMagicEmailerSyncContacts currently scans all DJs with emails and then skips synced contacts.
    Change it to process only contacts likely to need queue work:
    - DJs with emailsUpdatedAt newer than magicSyncedAt
    - DJs with magicSyncedAt NULL
    - pending/failed ledger rows whose retry_after has passed
    Keep the operation idempotent and safe to rerun.

[ ] Add orchestration and database smoke tests.
    Add tests that do not require hitting 1001Tracklists:
    - pipeline finalizes only after Magic queue summary is recorded
    - duplicate completion events do not double-count run history
    - resume fallback uses checkpoint or "a" safely
    - Magic ledger migration preserves existing rows
    - profile failure backoff excludes DJs until retry_after
    These tests should use fake emitters/stubbed stages where possible.

[x] Add persistent pipeline run history. Completed 2026-06-17.
    Create a pipeline_runs table or equivalent persistence that records each full run:
    - startedAt
    - finishedAt
    - status
    - duration
    - startLetter
    - djsFound
    - newDjs
    - profilesUpdated
    - emailsFound
    - emailsQueuedForMagic
    - errorSummary
    The UI should be able to show the last successful run from persisted data, not only server memory.

[x] Harden DJ detail updater for stability and efficiency. Completed 2026-06-17.
    Improve updateDJData.js without increasing CAPTCHA risk:
    - open updater Chrome minimized/backgrounded like the scraper
    - do not treat missing optional fields such as flags/social links as page-load failure
    - avoid overwriting existing useful profile data with empty extracted arrays
    - restart Chrome every 25-50 DJs to clear browser memory
    - batch searchable DJ count refreshes instead of querying after every DJ
    - make updater sleeps respond promptly to Stop
    Add deeper profile failure tracking later if needed:
    - profileErrorAt
    - profileErrorMessage
    - profileRetryAfter
    - profileFailureCount

[x] Add weekly scheduler and next-run display. Completed 2026-06-17.
    Add a configurable weekly background run, for example Tuesday at 02:00.
    The UI should show:
    - last successful run
    - next scheduled run
    - scheduler enabled/disabled
    - current running state
    Scheduled runs should use the same full pipeline flow as the button.

[x] Make resume-from-checkpoint the default for unfinished runs. Completed 2026-06-17.
    If the previous run did not finish, the main button and scheduler should resume from the checkpoint automatically.
    Manual starting letter should still be possible when explicitly supplied.

[x] Add scheduled-run quiet mode. Completed 2026-06-17.
    Scheduled runs should use calmer defaults:
    - minimized/background browser
    - slower scroll/crawl settings
    - longer CAPTCHA cooldowns
    - concise logs
    Manual runs can remain more verbose.

[x] Strengthen Magic Emailer sync ledger statuses. Completed 2026-06-17.
    Expand or harden the sync ledger to make integration safer:
    - pending
    - synced
    - skipped_already_exists
    - failed
    - retry_after
    - last_error
    - attempts
    The sync process should be idempotent and safe to rerun.

[x] Add contact dedupe and normalization before Magic Emailer sync. Completed 2026-06-17.
    Normalize and validate contact data before queueing or syncing:
    - lower-case email addresses
    - trim DJ names
    - canonicalize URLs where practical
    - dedupe the same email across multiple DJs
    - flag bad emails
    - optionally flag role/generic emails if useful

[x] Make weekly runs incremental. Completed 2026-06-17.
    Weekly runs should avoid reprocessing everything:
    - scan list pages for new DJs
    - update only stale or missing DJ profiles
    - search emails only for stale/missing email data
    - sync only contacts not already synced

[x] Replace noisy failure streams with health summaries. Completed 2026-06-17.
    The UI should still keep useful logs, but repeated noisy messages should be summarized into clearer health states:
    - CAPTCHA encountered: cooling down
    - page stalled: saved current DJs and moving on
    - 1001Tracklists unavailable: retrying later
    - Chrome restarted after letter to clear memory

[x] Add run-level summary counters to the UI. Completed 2026-06-17.
    The single status panel should expose concise run totals:
    - DJs scanned
    - new DJs inserted
    - DJ profiles updated
    - emails found
    - contacts queued for Magic Emailer
    - skipped/already synced contacts
